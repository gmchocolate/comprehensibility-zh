# 研究背景、证据边界与引用

## 1. 背景与研究依据

### 1.1 为什么需要另一个 Skill

现有的 Humanizer-zh（<https://github.com/op7418/Humanizer-zh>）主要关注空话、重复、模板化表达和作者声音的保留，也包含部分中文长定语与被动句检查。本项目与其**互补而非替代**：

| 维度 | Humanizer-zh | Comprehensibility-zh |
|---|---|---|
| 核心问题 | 说得是否自然、是否空泛 | 读者是否容易正确理解 |
| 优先目标 | 自然度、表达质量与保真 | 理解负担、阅读顺序与保真 |
| 修改尺度 | 常以句段局部编辑为主 | 句子、段落、整篇结构 |
| 长度导向 | 去掉无效重复，长度并非唯一目标 | 必要时允许变长，以减少推理负担 |
| 特别关注 | 模板句、套话、冗余表达 | 认知负担、知识门槛、逻辑桥梁 |
| 输出 | 润色稿 / 审阅建议 | 改写稿 / 问题诊断 / 保真审阅 |

**项目不应复制 Humanizer-zh 的 31 条规则或原文表达。** 若选择参考或复用该仓库代码/文本，需核查其对应版本许可证并保留适用的版权声明；默认采用本项目独立编写的规则。

### 1.2 科研启发：为什么“正确”不等于“好理解”

Clark、Martin、Mahowald 于 2026-10-21 发布的论文 *Why is AI-generated language so hard to understand?*（<https://arxiv.org/html/2610.29162v1>）研究了 AI 生成英语中的六类与阅读处理成本相关的语言特征：

1. **低频词语组合**（low-frequency n-grams）：词与词组合不常见，读者难以预测后续信息。
2. **较长句法依赖距离**（dependency length）：彼此相关的词隔得很远，增加工作记忆负担。
3. **宾语关系从句**（object relative clauses）：某些嵌套结构处理起来更费力。
4. **连续名词堆叠**（stacked noun compounds）：修饰关系压缩在一串名词里，可能产生歧义。
5. **名词临时转作动词**（denominal verbs）：要求读者临时推断非常规用法。
6. **不符合常规语义选择的无生命主语**（inanimate subjects）：某些动作与主语搭配不符合通常预期。

论文还通过长度惩罚训练实验，支持「优化目标偏好更高信息密度，可能使语言偏离人类习惯」的概念验证假说。这是本项目**设计动机**，不是直接的中文产品效果证据。

**证据边界必须明确：** 论文主要研究英语、有限模型和任务；使用语言处理难度相关特征作为代理指标，没有证明本项目的中文规则有效，也没有完成本项目所需的中文读者 A/B 理解实验。英文结构不应一比一映射成中文语法规则。本项目将其作为待检验的研究启发，而非既成结论。

### 1.3 核心原则：压缩文字 ≠ 压缩读者理解成本

例子：

- 原文：`基于多源异构数据融合的选址决策优化能力，可赋能门店增长。`
- 不合格的“简化”：`融合多源数据，优化选址，赋能增长。`（仍旧抽象，而且“增长”的含义没有依据）
- 更合适的改写：`系统把不同来源的数据放在一起分析，帮助团队判断一个位置是否适合开店。`（拆开抽象的动作与目的；不额外承诺增长结果）

好的可理解性优化不是“多用短句”这么简单，而是**把隐藏在表达中的必要关系显式化**，同时不添加超出来源的信息。
