# 研究背景与证据边界

## 这个项目想解决什么？

同一件事可以有两种表达：一种把信息尽量塞在一起，另一种让读者按顺序理解主体、动作、条件和结论。前者未必错误，却可能让人反复回看。

Comprehensibility-zh 将「**读者是否能正确理解**」作为编辑的首要目标，而不是「看起来是否像真人写的」或「能否缩短篇幅」。本项目仍是**编辑方法与 Agent Skill**，不是已验证的中文认知测量系统。

## 研究启发：一篇英语论文

论文：[Clark、Martin、Mahowald（2026），*Why is AI-generated language so hard to understand?*](https://arxiv.org/html/2610.29162v1)。

论文比较了 AI 生成英语与其他文本在多种语言现象上的差异，其中包括：

1. **较少见的词语组合：** 词组难以按熟悉的模式预测。
2. **较远的语法依赖：** 需要记住句首信息，读到句尾才能建立关系。
3. **复杂关系从句：** 嵌套让读者更难辨认谁做了什么。
4. **连续名词组合：** 多个名词紧贴，修饰关系不明确。
5. **名词临时作动词：** 读者需要额外推断词的临时用法。
6. **不符合通常预期的主语与动作搭配：** 读者需要重新理解动作关系。

论文还探讨了长度惩罚训练可能推动语言压缩的假说。**这不是「所有难读内容都由长度惩罚造成」的证明。**

### 哪些结论不能从论文直接推出？

- 研究重点是**英语**，不能把英语语法分类不加调整地直接用于汉语。
- 论文使用与语言处理难度相关的特征分析；这些特征并不等同于对本项目进行的中文读者理解实验。
- 论文没有运行或验证 `comprehensibility-zh`，不能用它给本仓库背书「理解率提升 X%」。
- 研究中的某些特征在专业写作中可能必要。不能因为某种搭配少见，就一律删掉。

因此，本项目**借鉴问题意识，不冒充实证结果**。

## 与 Humanizer-zh 是什么关系？

[Humanizer-zh](https://github.com/op7418/Humanizer-zh) 重点处理模板化措辞、套话、空泛与自然表达，也涉及部分中文句法问题。

本项目关注的是另一个判断：读者能否准确识别对象、条件、因果边界以及文章结构。两个项目有重叠，但目的和检查流程不同。本项目独立编写，不是对方的官方 Fork、翻译或授权派生版本。

## 对中文的工程化假设

以下是**待验证的设计假设**：

- 拆开多层定语，可能减少读者回读；但不能丢失限制条件。
- 将隐含但唯一确定的语义关系写明，可能降低理解歧义；但不能创造新事实。
- 对初学者先定义概念再谈结论，可能比先堆术语更好；对专家可能恰好相反。
- 文档按读者问题展开，可能减少篇章级迷路；但并非所有文体都适合「先结论后依据」。

这也是为什么 [设计与规则](DESIGN.md) 必须写明例外，[评估方法](EVALUATION.md) 必须同时检查**保真**和**理解**。
