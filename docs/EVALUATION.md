# 评估方法与发布验收

> 以下是研究与产品设计建议，非已完成的实证结果。

## 10. 评估体系：让“更易理解”成为可检验的目标

### 10.1 不使用的伪指标

- `AI 检测器判定为真人写作的比例` —— 与可理解性不等价。
- `改写后字数下降比例` —— 删除必要信息可能适得其反。
- `平均句长越短越好` —— 短句也可能断裂、含糊。
- `模型自评 9.8/10` —— 不能单独证明读者理解改善。
- `独立于上下文的术语数量` —— 必要术语删除可能损害精度。

### 10.2 核心衡量指标

| 指标 | 定义 | 优先级 | 说明 |
|---|---|---|---|
| **理解题正确率** | 读者读完后回答文章事实、条件、例外、因果边界的正确率 | P0 | 主要结果指标 |
| **事实保真率** | 原文独立命题保留比例 + 新增无依据命题数 | P0 | 上线阻断项 |
| **完成时间** | 阅读与答题耗时 | P1 | 在理解正确率不下降的前提下比较 |
| **主观理解难度** | 读者报告理解费力度 | P1 | 与客观测量相互印证 |
| **回读次数** | 为解决歧义重复阅读片段的次数 | P2 | 可由阅读实验记录，非必要 |
| **术语解释准确率** | 专业术语及其边界有无被误解 | P1 | 专业场景重要 |
| **无谓改写率** | 原本清楚的内容被改坏或无意义替换的比例 | P1 | 防止过度编辑 |
| **模型间稳定性** | 不同 Agent/模型对核心约束的遵循情况 | P2 | 衡量规则可迁移性 |

**建议主要判定逻辑：** 只有在事实保真没有明显下降、且理解正确率有可重复改善时，才宣称可理解性提升。若只有主观偏好提升，应明确说“读起来更舒服”，不要改称“理解准确率提高”。

### 10.3 测试集设计

初版至少包含六组文本：

1. **句法困难：** 长定语、复杂嵌套、跨度远的主谓搭配。
2. **语义歧义：** 人物指代、否定范围、条件关联、复杂比较。
3. **术语门槛：** SaaS 产品说明、技术参数、数据报告、科普内容。
4. **篇章结构：** 背景-结论顺序错误、段间缺桥梁、前后术语不一致。
5. **高风险保真：** 医疗、金融、法律、科研结论中的限定与否定。
6. **负样本（必须不改）：** 已经清楚的操作说明、精确术语、合同条件、代码和公式。

**建议首发门槛**：至少 30 条人工检查的公开合成案例，每组不少于 5 条；每条提供原文、目标读者、问题类型、保留点、允许改法和禁止改法。此门槛是**项目的目标要求**，不是已完成数据。

### 10.4 A/B 实验方法

用相同来源文本建立三个版本：

- `A` 原文
- `B` 经过 Humanizer-zh 或普通语言润色（作为一个比较基线）
- `C` 经过 Comprehensibility-zh

每位参与者**对同一篇文章只读一个版本**，避免记忆污染；不同文章在参与者之间做随机平衡。将读者按经验层级分组，盲化展示来源，不告知哪个版本由哪个 Skill 改写。所有版本先经过人工事实保真复核。

每篇设计 3–5 道问题：关键信息、条件/例外、因果边界、行动理解。记录正确率、耗时、阅读难度，预先说明成功条件。不要只选“优化后更好看”的例子；失败案例也应公开。

建议第一轮用 **20–30 篇文本、每种版本累计足够的独立读者回答** 作为探索性试验，再根据方差与目标最小效果量做正式样本量估算。这里不给出未经计算的统计显著性承诺。

### 10.5 自动化测试与人工评审分层

- **静态检查（可 CI）：** frontmatter 可解析、文件结构存在、内部引用有效、测试样本字段齐全。
- **语义约束检查（需人工/模型辅助）：** 数字、主体、条件、否定、推断程度没有漂移；发现风险须人工确认。
- **可理解性评估（需真人）：** 理解题、读速与回读情况；不能由上述静态检查替代。

## 14. 发布路线与验收清单

### Phase 0：仓库可用（首发）

- [ ] 根目录 `SKILL.md` 有合法 frontmatter 且可被支持的 Agent 发现。
- [ ] `README.md` 明确项目差异、安装、模式、示例和限制。
- [ ] 至少 30 个公开合成测试案例，覆盖规则、保真、无修改和歧义拒改。
- [ ] `MIT LICENSE`、`CONTRIBUTING.md`、`CHANGELOG.md` 完备。
- [ ] CI 静态校验通过。
- [ ] 至少手动验证 Claude Code、Codex、Cursor 中实际可用的客户端（分别记录版本和结果；不能测试就注明未验证）。
- [ ] 明确声明未做真人实验，不宣传“提高理解率 X%”。

### Phase 1：规则质量

- [ ] 至少 50 个高质量案例，包含非必要改写的反例。
- [ ] 多个模型执行相同测试并记录可复现的差异。
- [ ] 建立保真失败分类：新增事实、遗漏条件、归因漂移、时间漂移、过度简化。
- [ ] 补充 Markdown 结构和内链保护测试。

### Phase 2：实证评估

- [ ] 预注册或公开 A/B 实验方案、文本选择与主要指标。
- [ ] 实验中采用真正不同参与者与盲化文本版本。
- [ ] 展示正向、无效和负向样本，报告效应区间与限制。
- [ ] 仅在真实数据充分时更新 README 中的效果表述。

### 首发质量底线

1. **可安装：** 支持 Agent 可以加载真实的 `SKILL.md`。
2. **可执行：** Agent 能在示例任务中按指定模式完成审阅或修改。
3. **可保真：** 在测试中不能把歧义变成未经证实的具体事实；不得篡改硬约束。
4. **可回退：** 原文清楚时应保持不变；审阅模式不触碰原文。
5. **诚实：** 所有指标与结论注明“实验数据”还是“项目设想”。
