# 如何验证文字真的更容易理解？

**先区分三件事：** 文档和测试数据是否完整、改写是否保留原意、真实读者是否理解得更好。它们需要不同的验证方法，不能互相替代。

本仓库目前提供 **36 个合成案例和自动化静态检查**；**没有中文真人理解实验结果**，也没有跨模型效果排名。

## 一、什么不能当作理解效果

- **字数减少：** 删除必要条件可能让文章更短，却更容易误解。
- **句子变短：** 拆句后如果条件与结果脱节，反而更难懂。
- **AI 检测得分：** 不是读者理解正确率。
- **模型自评：** 模型觉得自己写得好，不等于读者看得懂。
- **主观喜欢：** 文风顺畅可以改善体验，但不能单独证明事实理解更准确。

## 二、先守住事实保真

在让真人阅读之前，先由编辑之外的审阅者核对原稿和新稿。

| 核对项 | 要回答的问题 | 不通过的例子 |
|---|---|---|
| 独立命题 | 原文每个有实际意义的信息是否仍在？ | 删除「部分功能尚未开放」 |
| 新增主张 | 新稿是否出现无来源的事实或因果？ | 擅自增加客流、收入预测 |
| 主体与对象 | 谁做什么、影响谁是否相同？ | 把操作人换成管理员 |
| 逻辑条件 | 「仅当」「并且」「或者」「除非」的含义是否保留？ | 把必要条件写成充分条件 |
| 时间与状态 | 日期、范围、计划、完成状态是否一致？ | 「尚未通过」变「测试失败」 |
| 专业与结构 | 数值、单位、代码、链接和引文是否未受损？ | 改写 HTTP 状态码或 JSON 字段 |

**硬性处理：** 发现有根据的严重保真错误，先修复或撤回改写，不进入宣传「理解提升」的阶段。无法确定原意时，应由原文作者确认，不能以模型投票决定。

## 三、合成案例：检查能不能识别问题

[`tests/fixtures.json`](../tests/fixtures.json) 提供六类、共 36 条人工构造的测试输入：

| 分类 | 主要风险 | 例子 |
|---|---|---|
| A：句法 | 长定语、动作关系、条件 | 复杂条件是否被误解 |
| B：词语与指代 | 生造组合、术语、代词 | 「他」指向不唯一 |
| C：信息组织 | 信息过密、跳步、重复 | 条件和结论被挤在一句中 |
| D：篇章 | 顺序、论据、标题与冲突 | 不同章节相互矛盾 |
| E：专业文本 | 协议、科研、医疗、法律、创作 | 保留 429、工作日和可能性 |
| F：边界 | 零修改、歧义、限定与内容保护 | 「受邀企业」不能变成「所有企业」 |

每条案例都有读者、原文、期望行为及禁止改法。**这些字段不是模型自动生成结果**，也没有「标准答案必须逐字相同」的要求。案例编号与 [36 个规则](DESIGN.md) 一一对应，用于检查覆盖是否齐全。

运行结构检查：

```bash
python -m unittest discover -s tests -v
```

测试会检查：Skill 元信息、规则 ID、案例字段、重要文档内部链接、文件结构和部分高风险示例；不会运行语言模型、审查实际改写质量或模拟真人阅读。

## 四、如何设计真实读者实验

**实验问题：** 与原文相比，这种改写是否让预先指定的目标读者更准确、更省力地理解？

建议比较三种版本：

- **A：** 原文。
- **B：** 常规润色稿（如普通编辑或另一套编辑 Skill），作为比较基线。
- **C：** 使用本 Skill 的改写稿。

在生成 B/C 版本前统一读者与编辑范围；由独立审阅者先检查保真。不要先看结果再挑选特别成功的文本。

### 对每位参与者

1. 记录目标读者画像：专业背景、语言熟悉程度、与主题相关的经验。
2. 对**同一篇文章**只呈现 A/B/C 其中一个版本，随机分配；不同文章进行平衡，减少先读某个版本的记忆影响。
3. 不告诉参与者哪个版本由哪个工具改写。
4. 读完后回答 3–5 道提前写好的题，至少覆盖关键事实、条件或例外、推断边界与实际操作理解。
5. 记录答题正确率、阅读及答题耗时、主观理解难度；必要时记录回读次数。
6. 同时收集阅读题本身是否有歧义，避免把题目缺陷当成文本缺陷。

**推荐先做探索性试验**：挑选 20–30 篇不同类型的中文文本，并收集足够的独立读者回答，了解难度和方差。正式实验再按预期效应、统计功效、聚类结构做样本量计算；不能直接凭参与者数量宣称显著。

### 如何解释结果

| 观察 | 可以说什么 | 不应说什么 |
|---|---|---|
| 理解题正确率提高，保真审核通过 | 在本次人群与材料上观察到理解改善 | 对所有中文文本都有效 |
| 读者更喜欢，但答题结果没变 | 主观阅读体验有所改善 | 证明理解更准确 |
| 阅读时间缩短，答题变差 | 可能更快，但理解质量受损 | 效率全面提高 |
| 静态测试全部通过 | 仓库结构与案例格式符合要求 | Skill 通过真人理解验证 |
| 不同模型输出不一致 | 模型间稳定性仍需验证 | 某一个模型绝对更好 |

报告应同时给出失败案例和负面结果；如有正式统计分析，说明样本选择、置信区间、分析方法与局限性。
