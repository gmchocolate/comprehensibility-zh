# Comprehensibility-zh · 中文可理解性优化 Skill

> **不是让文字更短，而是让理解更轻松。**  
> *Clearer Chinese, without losing meaning.*

Comprehensibility-zh 是一个开源的中文文本审阅与改写 **Agent Skill**。它帮助你找出并修复那些“说得对，却很难读懂”的表达：长定语、多层嵌套、指代不明、术语门槛、信息过度压缩、段落跳跃和不符合读者理解顺序的文章结构。

**首要约束：事实保真。** 不编造新信息，不将推测改成事实，不删除例外、条件、数字、引用或作者立场。

## 它和 Humanizer-zh 有什么不同？

[Humanizer-zh](https://github.com/op7418/Humanizer-zh) 侧重删掉无效重复、套话与模板化表达，让文字更自然。**Comprehensibility-zh** 侧重让读者更容易正确理解信息，允许为了减少认知负担而拆句、补充原文已蕴含的解释、调整获授权的阅读顺序。两个工具互补，互不依赖，也没有官方隶属关系。

|  | Humanizer-zh | Comprehensibility-zh |
|---|---|---|
| 重点 | 自然度、套路表达 | 理解负担、信息结构 |
| 目标 | 更自然地表达 | 更容易准确地理解 |
| 篇幅 | 去除无效重复 | 必要时可适度变长 |
| 底线 | 保留事实与作者声音 | 保留事实、限定与逻辑关系 |

## 安装

使用支持 [Agent Skills](https://agentskills.io) 的客户端。使用以下命令安装：

```bash
npx skills add gmchocolate/comprehensibility-zh
```

也可以克隆仓库，将包含 `SKILL.md` 的目录放入客户端支持的 Skill 目录。不同客户端的发现路径及功能可能有差异，以对应版本的文档和实测为准。

> 本 Skill 仍处于早期版本，尚不宣称所有 Agent 客户端均已完成实测验证。

## 快速使用

**标准优化（默认）**

```text
用 comprehensibility-zh 优化以下内容，让不了解行业的人也能读懂。
保留全部事实、数字和限定；允许适当增加句子；只输出改写稿。

原文：该平台提供跨部门任务状态协同跟踪能力。
```

**只审阅、不改文件**

```text
用 comprehensibility-zh 的 review 模式检查 docs/architecture.md。
指出理解障碍、原文位置、原因和改法；不要编辑文件。
```

**面向客户重构阅读顺序**

```text
用 comprehensibility-zh 的 deep 模式重构这篇产品介绍。
目标读者：第一次了解我们产品的客户。
允许重排章节，但不能编造功能、客户案例和业务数据。
缺少的信息请单独指出，不要自行补齐。
```

## 四种模式

| 模式 | 用途 | 是否改结构 |
|---|---|---|
| `review` | 定位真正的理解障碍，只给建议 | 不改文件 |
| `light` | 最小幅度修复难懂句子 | 基本不改 |
| `standard` | 优化句子、术语、段落衔接（默认） | 可局部调整 |
| `deep` | 按读者问题重建全文阅读顺序 | 仅授权后调整 |

默认只输出最终稿。没有需要修改的地方时，可以返回原文。

## 改写示例

**改写前**

> 对于在提交申请后未在规定期限内完成身份核验且未主动撤回申请的用户，系统将自动终止申请流程。

**改写后**

> 用户提交申请后，如果没有在规定期限内完成身份核验，也没有主动撤回申请，系统会自动终止申请流程。

保留原有条件和结果，只调整读者处理信息的顺序。

**不能擅自改写的情况**

> 张老师把资料交给李老师后，他发现有两页缺失。

“他”所指不唯一。Skill 应指出歧义，而不是猜测到底是谁发现缺页。

更多正例、反例见 [`examples/examples.md`](examples/examples.md)。

## 核心原则

1. **准确高于通俗**：不能为了好懂改变事实、因果、概率、时间、条件、归因或结论。
2. **理解高于字数**：短未必好；必要时保留有意义的重复、条件与专业名词。
3. **阅读路径高于表面润色**：先定位读者不懂的原因，再决定是否改词、拆句或重排。
4. **最小充分修改**：原文清楚则不改，专业文体不强行口语化。
5. **安全边界**：未经授权不写文件；代码、公式、数据、链接、ID 等受保护。

详见 [`SKILL.md`](SKILL.md) 与 [`docs/DESIGN.md`](docs/DESIGN.md)。

## 效果如何验证？

本仓库提供**结构测试和合成编辑案例**，但没有把这些测试冒充真人理解实验。真正的效果指标应包括读者理解题正确率、事实保真、阅读耗时和错误理解率，而不是“AI 检测通过率”“句子变短多少”或模型自评分。详见 [`docs/EVALUATION.md`](docs/EVALUATION.md)。

**当前限制：** 本项目尚未开展足以证明提升幅度的中文真人实验。它不是 AI 来源检测器、自动事实核查器或专业意见替代品。
