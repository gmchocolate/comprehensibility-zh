# Comprehensibility-zh｜让中文更容易理解

> **不只把话说顺，而是让读者更容易读懂，同时不改变原意。**  
> *Make Chinese easier to understand, without changing its meaning.*

Comprehensibility-zh 是一个开源的中文审阅与改写 **Agent Skill**。它帮助写作者发现：信息明明在文章里，读者为什么还是看不懂、需要回读，甚至会理解错。

它处理的不只是生硬词句，还包括条件藏得太深、代词指向不清、术语先于解释出现、段落之间突然跳转，以及整篇文章没有按读者的问题展开。

**使用底线：事实和原意优先。** 不能为了通俗而增加未经证实的事实、删除条件，或把「可能」改成「一定」。原文本来清楚，就可以不改。

## 先看一个例子

**原文：**

> 对于在提交申请后未在规定期限内完成身份核验且未主动撤回申请的用户，系统将自动终止申请流程。

**改写：**

> 用户提交申请后，如果没有在规定期限内完成身份核验，也没有主动撤回申请，系统会自动终止申请流程。

核心变化不是缩短字数，而是让读者按「提交申请 → 两个条件 → 处理结果」的顺序理解，同时保留原文的条件关系。

再看一个**不能猜着改**的例子：

> 张老师把资料交给李老师后，他发现有两页缺失。

这里的「他」可能指两个人。Skill 应要求作者明确指代，而不是自己选一个答案。更多正反例见 [示例集](examples/examples.md)。

## 安装

在支持 [Agent Skills](https://agentskills.io) 的客户端中，可以尝试：

```bash
npx skills add gmchocolate/comprehensibility-zh
```

也可以克隆仓库，按客户端的说明安装根目录 `SKILL.md`。不同客户端对 Skill 的发现与调用方式可能不同；**仓库暂未完成跨客户端安装兼容性实测**，请根据所用工具的版本验证。

## 直接使用

把下面这段与待改文字一起交给支持该 Skill 的 Agent：

```text
请使用 comprehensibility-zh 的 standard 模式改写以下内容。
读者：第一次接触这个领域的普通成年人。
要求：保留事实、数字、时间、条件、否定和不确定性；
不补造案例或功能；原本清楚的地方不必修改。
输出：只给改写后的正文。

原文：该平台提供跨部门任务状态协同跟踪能力。
```

如果你希望 Agent **直接编辑仓库文件**，需要明确给它文件路径和修改权限。例如：

```text
使用 comprehensibility-zh 的 deep 模式处理 README.md 和 docs/ 下的中文文档。
读者：第一次使用本项目的开发者。
授权修改标题、段落与章节顺序；不要改代码、命令、链接目标和数据。
请先核对跨文件术语、规则编号及引用，再提交改动和检查结果。
```

如果只想知道哪里难懂、不修改文件：

```text
使用 comprehensibility-zh 的 review 模式审阅 docs/architecture.md。
按严重程度列出具体位置、理解障碍、改写建议和需作者确认的地方。
不要写入任何文件。
```

## 选哪种模式？

| 模式 | 适合做什么 | 修改范围 |
|---|---|---|
| `review` | 找出读者可能误解或读不顺的地方 | 只报告，不修改 |
| `light` | 尽量少改，修复明显难懂的词句 | 词句级 |
| `standard`（默认） | 兼顾句子、术语与相邻段落 | 局部调整 |
| `deep` | 按目标读者的疑问重新组织整篇内容 | 仅在得到授权时重排结构 |

**模式不等于输出形式。** 通常直接交付改写稿；需要核查改动时，也可以要求「问题清单」「前后对照」或「改写稿 + 重要修改说明」。`review` 始终只报告。

## 这套 Skill 会如何判断？

它会按以下顺序工作：

1. **确定读者和范围：** 谁会看、要完成什么任务，哪些内容允许修改。
2. **保留原意：** 记录主体、动作、数字、时间、条件、否定、程度和证据归属。
3. **定位问题：** 是难词、复杂句、信息过密，还是整篇文章的说明顺序不合理。
4. **最小充分改写：** 只修改真的妨碍理解的部分；必要时拆句或调整阅读顺序。
5. **双向核对：** 原文的信息是否都留下了？新稿有没有加入原文没有的事实？

详细操作在 [SKILL.md](SKILL.md)，[36 个检查点](docs/DESIGN.md) 提供具体判断依据。规则是辅助判断，不是看到某个词就必须删除的黑名单。

## 哪些事情它不能做？

- **不能替你补充事实。** 原文没提供数据、产品能力或原因，Skill 不会为了写得具体而编造。
- **不能自行解决真实歧义或矛盾。** 两个来源互相冲突时，应该指出冲突，请作者核实。
- **不能证明内容真实。** 它保留原有说法，不等于已经从外部核实。
- **不能代替专业审校。** 法律、医疗、金融、科研文本尤其要检查定义、限定和风险表述。
- **不能凭静态测试声称「提高了理解率」。** 真实提升需要中文读者实验支持。

## 与 Humanizer-zh 的关系

[Humanizer-zh](https://github.com/op7418/Humanizer-zh) 侧重处理模板化表达、空话与语言自然度。本项目更关注**读者能否正确理解词句、条件、概念和全文结构**。两者可以互补，但彼此独立；本项目不是 Humanizer-zh 的官方版本或 Fork。

项目的研究启发之一是 [*Why is AI-generated language so hard to understand?*](https://arxiv.org/html/2610.29162v1)。该论文讨论的是**英语**生成文本中的语言处理特征，**没有验证此中文 Skill 的效果**。详见 [研究背景](docs/RESEARCH.md)。

## 目前验证到什么程度？

仓库提供 **36 个合成案例**及本地 / CI 静态校验，用于检查文档、规则编号与案例格式的一致性。运行：

```bash
python -m unittest discover -s tests -v
```

这些测试**不会调用模型，也不会让真人阅读文章**。关于真人理解题、事实保真与盲测方案，请看 [评估方法](docs/EVALUATION.md)。尚无可靠数据可以宣称某个百分比的阅读理解提升。
